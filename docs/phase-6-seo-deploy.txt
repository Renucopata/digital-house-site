5. STYLES
==========================================================================================
No token, font, spacing or motion changes.
Window shadow: was an inline SVG with a 12px CSS blur filter re-painted on every frame that touched
  the hero/contact sections; now the blur is baked into a 300x200 WebP (alpha = shape) used as a
  mask over --texture-ink. Using it as a mask (not a background image) keeps the theme color and
  prevents Chrome from picking the shadow as the page's Largest Contentful Paint element (it did,
  as a background image, during this phase).

8. HOW TO RUN / TEST
==========================================================================================
  npm run lint → passes · npm run build → passes (routes: /, /styleguide, /robots.txt,
  /sitemap.xml, /opengraph-image.png, /twitter-image.png, /icon.png, /apple-icon.png)
Checked on the production build (localhost):
  /robots.txt → "User-Agent: * / Allow: /", Host + Sitemap with the D24 URL.
  /sitemap.xml → one <url>: https://digital-house-site-indol.vercel.app/
  <head> → canonical, og:title/description/url/site_name/type, og:image (+ width 1200, height 630,
    alt, type), twitter:card summary_large_image + image; JSON-LD present and valid JSON.
  /styleguide → <meta name="robots" content="noindex, nofollow">.
  Screenshots 1440 / 768: no horizontal overflow, all images load, window shadow unchanged.
Lighthouse 13.5.0 (npx), localhost production build, 5 runs each, medians:
  Mobile (default settings):  Performance 92 (runs 90–93) · Accessibility 100 · Best Practices 100
                              · SEO 100 — LCP 3.2 s, TBT 114 ms, FCP 1.0 s, CLS 0
  Desktop:                    Performance 100 · Accessibility 100 · Best Practices 100 · SEO 100
                              — LCP 0.7 s, TBT 5 ms, FCP 0.3 s
  (machine benchmarkIndex 1220–1840 during these runs)
Caveat: earlier runs in this phase were made while the laptop was heavily loaded by other programs
  (benchmarkIndex ≈ 585, Lighthouse warned "slower CPU than Lighthouse expects") and scored 74–79.
  Local scores depend on machine load — after deploying, confirm with https://pagespeed.web.dev.
